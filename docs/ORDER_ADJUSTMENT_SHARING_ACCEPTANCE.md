## 2. 订单调价应有的结果

入口：**订单 → 订单详情 → 费用协商**。此处展示原订单金额、累计补款、已退差额、当前金额；打手及有权限的管理者可查看原费率下的分账明细，聊天室保留原因、同意及资金结果证据。

| 操作 | 买家 | 本单打手 | 关联俱乐部负责人 / 平台管理员 | 无关账号 |
| --- | --- | --- | --- | --- |
| 查看本单协商记录 | 可以 | 可以 | 可审阅有权限的本单 | 不可以 |
| 发起加价 | 不可以 | 可以 | 不代替当事人发起 | 不可以 |
| 发起减价 | 可以 | 可以 | 不代替当事人发起 | 不可以 |
| 同意 / 拒绝 | 另一方发起时可以 | 另一方发起时可以 | 不代替双方同意 | 不可以 |
| 撤回 | 自己发起且尚未进入资金处理时 | 同左 | 不代替双方撤回 | 不可以 |
| 支付加价差额 | 可以 | 不可以 | 不代付 | 不可以 |
| 同步原补款 / 退款 | 可以 | 不授予该资金接口权限 | 仅平台管理员可以 | 不可以 |

- 打手提出加价后，买家明确接受，再选择微信或余额补款；只有后端核验成功才改金额及三方待结算款。接受加价、拉起支付、客户端显示成功均不单独入账。
- 买卖任一方提出减价，提交即表达本人同意，另一方同意后按各笔原支付退差；全部相关退款成功才下调净价。全额退款仍走原售后流程，不能用减价把净价改成0。
- 正常履约中可加减；已完成且仍在7天售后期、资金未结算时只可减。已结算、已退款、争议及裁决边界由后端拒绝自动调价。
- 订单继续使用创建或领取时冻结的费率。修改平台自由打手费率、平台挂靠费率或俱乐部佣金，仅影响相应新订单，不能重算旧单费率。
- 微信款按原微信支付退款，银行卡原付款不承诺退到零钱；余额款恢复原充值与收入分区，不把充值款变成可提现收入。多次补款、退差及最后全退都逐笔保留原付款与剩余退款容量。
- 活动协商需先回应、撤回或同步解决；资金未知时保持冻结。旧方案迟到款另行退款，不阻塞后来正常订单或新协商。刷新、双击、重复通知不能重复扣款、退款或增加收入。

核账示例：原付100元 → 补20元 → 退差5元，应显示原价100、累计补款20、已退差5、当前115元。若该单原冻结的平台率5%、俱乐部率10%，净分账应为5.75、11.50、97.75元；这里的比率仅为例子，不能作为系统默认值。随后整单全退，应再退115元，累计退120元，不遗漏补款、不重复退已退的5元。

### 到期、异常与迟到款

1. 普通方案有效期24小时，尚未发起付款的到期方案可失效。微信建单后不因用户取消、网络超时或普通404直接解除。
2. 微信补款原单号与截止时间固定，不能通过重试延长。临近到期不新建支付会话；在途创建有有限租约，旧请求只能清理自己的租约。
3. 到期同步先查微信原单，确认关闭，或在租约结束后取得可信查询及关单不存在结果，才结束原方案。无签名404、网络错误仍属未知，继续沿原单查询。
4. 已结束方案收到鉴真的迟到实付，单独登记并按该原交易退款；不增加订单净价、GMV或佣金，也不变成可提现收入。退款终态显示“迟到补款已退还”。
5. 微信退款异常、关闭或超时均保留冻结和原因，不自行改成成功；通过原记录同步并联系平台核账。测试到期及交错竞态使用隔离测试夹具，禁止改生产账本、付款时间或服务器时钟。

## 3. 发布前配置顺序

1. 将本轮后端部署到对应环境，先核对版本及健康状态；启动迁移前按[部署流程](DEPLOYMENT.md)备份数据库、私密配置和加密主密钥。本轮本地构建记录不能证明线上后端已升级。
2. 服务端配置实际小程序AppID/AppSecret；前端AppID与之对应。生产设`DEV_MODE=false`，正式API为`https://game.ai.58it.cn/api`。AppSecret、APIv3密钥和私钥仅留服务端，不入前端、Git、截图或销售包。
3. 微信公众平台配置`https://game.ai.58it.cn`等实际使用域名的request、downloadFile、uploadFile合法域名，核对HTTPS证书和图片可达。
4. 平台管理员进入**我的 → 平台管理 → 微信支付**，填写真实商户号、商户证书序列号、APIv3密钥、商户私钥、微信支付公钥及公钥ID。秘密留空保留已存值；普通用户与俱乐部负责人不能访问商户配置。
5. 核对三类公网通知地址，路径保留如下；通知由服务端验签解密，不添加小程序会话登录拦截。
6. 导入`frontend/dist/release/mp-weixin`，核对正式域名校验后上传、审核、发布。包中必须有`pages/shares/detail`和`pages/requests/detail`；需要重新构建时沿用仓库正式发布脚本，不上传本地调试包。

| --- | --- |
| 支付 | `https://game.ai.58it.cn/api/payments/wechat/notify` |
| 退款 | `https://game.ai.58it.cn/api/payments/wechat/refund-notify` |
| 商家转账 | `https://game.ai.58it.cn/api/payments/wechat/transfer-notify` |

### 新版商家转账与提现

平台管理员进入**平台管理 → 钱包管理 → 商家转账配置**，沿用支付配置中的商户及签名/验签材料，再填写：

| 字段 | 要求 |
| --- | --- |
| 启用真实提现 | 商户能力和配置齐备后开启 |
| 转账场景编号 | 商户实际获批、适合本业务服务收入的场景 |
| 场景报备字段 | 按获批要求添加；最多10项，名称1—15字、内容1—32字 |
| 通知地址 | 上表转账地址，无查询参数 |
| 转账备注 / 收款感知 | 分别最多32字 / 10字，按实际场景填写 |

采用新版`/v3/fund-app/mch-transfer/transfer-bills`；本人待确认收款时调用小程序原生`wx.requestMerchantTransfer`。接口创建响应、页面“已就绪”和本人点确认都不代表最终到账，后端仍需查原商户单或处理已验签通知。

个人：**我的 → 我的钱包 → 提现**。俱乐部：负责人进入**俱乐部控制台 → 资金管理 → 提现**，佣金转入当前负责人的实名微信。平台管理员在**钱包管理 → 资金来源审核 → 对应申请明细**逐笔核对来源，再“审核并发起转账”；执行时服务端再次核验。充值、成员托管押金、俱乐部平台押金及来源缺失收入都不能作为佣金提现。

平台不另设最低门槛，但0元不能转账；当前真实通道个人至少0.10元，俱乐部因负责人实名核验至少0.30元，个人单笔达到2000元也须实名。最终限制以商户获批能力及微信实际返回为准。每天按北京时间自然日一次；处理中及成功占用次数，明确失败或平台拒绝后可再申请。服务收入需先过7天售后并无争议；测试不要为加速真实提现改账。

## 5. 用户逐项测试清单

先准备买家A、本单打手B、关联俱乐部负责人C、平台管理员D及无关账号E。使用非演示服务与需求，记录环境、版本、时间及订单/申请ID；真实资金单与本地模拟单分开记录。

### 订单与账本

- [ ] A下单实付；B提加价，A先拒绝，再由B重提并接受。接受后原价不提前变化；取消支付不增加收入，随后“同步原单”恢复真实状态。
- [ ] 完成一次微信补款、一次余额补款，再由A、B分别发起减价并由对方接受；对照第2节示例核对原价、累计实付、累计退差、净额和分账，聊天室证据完整。
- [ ] 连续提交相同内容的新方案能得到新记录；同一次未知提交重试不生成两笔。双击付款或同步不得重复扣款。
- [ ] 余额混合支付后退差，充值仍为充值、收入恢复原用途；微信退款核对原支付渠道实际到账。
- [ ] 多次加减后申请整单退款，核对每笔初付/补款的累计退款容量及钱包反冲；不能重复退已成功差额。
- [ ] D修改费率后，旧单维持原比例，新单取新配置；自由打手与挂靠打手分别测试。C和D可审阅但不能替A/B同意，E不可读取本单。
- [ ] 完成后未结算仅能减价；争议、已结算、已退款不可自动调价。7天结算后个人/组织收入及来源合计正确。到期、迟到、断网及异常回调的破坏性场景以隔离自动回归记录验收，不改真实资金数据。

### 提现与实名

- [ ] 阅读“提现规则”弹框，核对最低金额、每日一次、7天售后及充值不可提现；测试0、超余额和重复申请被拒绝。
- [ ] D在来源审核页看到每笔付款、订单及本次分配金额，来源合计等于申请额；异常来源不能审核出款。C仅能提现本组织佣金，到账人为当前负责人。
- [ ] 待审核拒绝后资金只解冻一次；审核后若进入处理中，只能同步原单，不能用拒绝把已出网资金解冻。
- [ ] 实机完成原生收款确认，再同步到微信最终成功；分别记录申请、来源审核、微信确认、最终资金到账。取消、未知结果、明确失败也核对原单状态及每日次数，不能拿一次确认代替全部验收。
