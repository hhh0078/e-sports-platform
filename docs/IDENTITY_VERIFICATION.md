# 姓名与身份证核验

文件作用：记录身份证二要素核验的状态、支付门槛、密钥配置和验收边界，不包含真实密钥或身份证资料。

## 用户状态

- `users.data.is_minor` 为“是否未成年或尚未完成核验”，新用户、历史缺失或异常数据均默认 `true`。界面将未核验状态显示为“待核验”，不将其描述为已经确认的未成年人。
- 服务端先验证18位身份证的格式、校验位和合法生日，按上海自然日判断满18周岁。未满18周岁直接返回 `IDENTITY_UNDERAGE`，不调用外部接口。
- 只有外部 HTTP 200、业务 `code=200`、`data.result=true` 均成立后，才在同一事务合并私密核验事实并将用户标志改为 `false`。
- 支付资格同时要求用户标志为 `false` 和服务端私密核验事实有效；普通资料接口、客户端缓存及开发模式不能直接授予资格。
- 平台不保存完整姓名、完整身份证、地址、性别或出生日期；仅保留必要的核验时间、来源、成年通过事实、请求摘要、脱敏信息和同意时间。核验秘密不进入审计及日志。

## 进入提醒与交易

- 首次进入显示防沉迷提示，可选择继续浏览。已显示提醒在本机保存已读标志，重新进入或切换页面不重复自动弹出；主动入口和交易前核验不受已读标志影响。
- 未核验用户下单、发布付费需求、订单微信或余额付款、加价补款、充值及各类押金付款前，需完成身份核验。
- 前端每次发起交易检查服务端最新状态，后端在交易入口和支付事务中重新读取用户表及私密事实。禁止用一次前端检查代替后端支付检查。
- 接单、发布服务、退款、原单查询、支付成功回调和存量资金退出不因本次新增门槛被阻断。
- 弹框显示未成年人拒绝文案；接口调用失败显示提供方 `msg`，一致性失败显示 `data.desc` 或明确失败文案。超时、格式异常、配置缺失和并发重复请求均不会授予支付资格。

## 管理员配置

后台“身份核验”页面配置 API Key，留空保存保留原值。平台管理员可编辑，普通账号无权访问。读取仅返回是否配置，不返回密钥及密文。

密钥使用现有 `CONFIG_ENCRYPTION_KEY` 以 AES-GCM 和独立用途标签加密，保存在独立 `settings/identity-private` 记录；未配置主密钥时拒绝保存。接口地址固定为 `https://v2.xxapi.cn/api/idCardCheck`，不允许后台更改为任意地址；禁止重定向转发秘密。

请求为 `POST application/x-www-form-urlencoded`，参数 `name`、`idcard`，密钥通过 `Authorization: Bearer <access_key>` 发送。只允许服务端调用，单次有超时及响应体大小限制，并按账号限制频率和并发，避免反复点击重复调用。

上线时由管理员在配置页填写真实密钥。真实密钥不得写入源文件、测试夹具、截图、提交或本文档。已有管理员维护的协议需同步说明成年人交易要求、收集目的和二要素服务提供方；默认协议更新不覆盖已有自定义正文。核验表单单独取得本次提交姓名及身份证的同意。

## 验收边界

自动验收需要覆盖18岁生日当天及前一天、闰日、非法日期及校验位、未成年外部调用为零、不一致、提供方错误、超时、异常响应、密钥不回显、用户标志伪造无效、旧订单及多种支付入口、首次提醒去重与换号迟到响应。

真实姓名身份证的一致性、真实微信设备交互、真实商户付款和上线后的密钥配置需单独记录；本地模拟外部响应不能作为这些项目的通过证据。
