# 输入框焦点布局与账户余额显示验收

文件作用：记录2026-10-26本轮输入框样式修复、钱包合并展示和本地回归证据；生产、微信实际页面及真机能力与自动测试分开记录，不把编译成功视为真实设备验收。

## 实施范围

- 共享原生输入框使用正常文字行高；带 `.input` 的 `input` 与 H5 `uni-input` 使用明确控件高度、块布局和零上下内边距，表单分节的高权重规则遵守相同约定。带图标的容器、textarea、字号与原生键盘避让继续保持原职责。专用搜索／昵称输入由对应页面样式与级联回归覆盖。
- 钱包只合并展示，不合并资金记账：个人中心和钱包主额改为“账户余额”，直接使用服务端 `spendable_cents`，下面明确“其中可提现 ¥…，充值仅用于消费”。删除重复的独立充值余额行；进行中、结算中、提现中和押金仍分别保留。
- 提现金额与资格继续使用 `available_cents`，充值不可提现；界面代码不生成到账事实、调整账本或改变支付接口。已登录但数据缺失／无效显示“—”，访客显示零，旧账号余额不外泄。
- 先行局部设计使用内置 ImageGen；两张最终设计图均为390×844，保持原有自然黑绿主题及现有布局。未添加依赖；输入与钱包改动不涉及资金迁移。另行授权的线上服务承接见 [独立验收记录](SERVICE_CONVERSION_ACCEPTANCE.md)。

## 微信输入实际检查

- 工具为微信开发者工具Stable 2.02.2608040，基础库3.17.4。`scripts/mini-input-focus.ts`使用官方SDK的公开节点、真实tap、输入、hideKeyboard与截图，不调用Vue实例、不注入token或页面内部data。
- 两宽度分别覆盖普通商户输入、密码、多行证书、资金金额、服务标题、颜色值、游戏搜索、首页搜索。各场景保存空值聚焦前后、有值聚焦前后、相邻切换（适用时）和失焦；外框、同页相对位置与原始像素分开核对。
- `output/input-focus/mini-320/report.json`与`mini-390/report.json`各有8项检查、44次测量及44张完整原始截图，全部通过且真实退出；`comparison-*`只在固定共同边界裁剪拼排原始像素，不重新绘制页面。主任务逐组检查了16张对照图，没有发现占位文字或相邻字段上跳。
- 首页有值时会显示清除按钮，正常占据横向空间；测试比较相同内容状态的焦点前后，不将清除按钮造成的变窄误判为聚焦跳动。
- 在320模拟器另外使用原生电脑鼠标实际点击金额输入及支付配置商户号、切换证书输入并失焦。原生可访问性确认输入框真正获得焦点，截图可见光标，未见同页占位文字上移；证据为`physical-finance-320-*`与`physical-payment-320-*`。
- 新独立工程导入被开发工具当前失效的系统代理阻断，因此保留原开发包完整快照，将本地18091编译包暂时置于已打开工程，并通过原生工具重新编译。运行前校验本地API、dev_mode及包内容，未用正式API做表单操作，未改变系统代理。本地测试API不启动AI或订阅发送worker。
- 钱包320首次完整通过；390初次在登录俱乐部负责人后的路由断言失败，实际落在个人主页，原始证据保存在本地诊断目录。源码没有资金页跳个人主页的路径；收紧SDK的登录可操作/可见账号卡、本次昵称和转场稳定校验后，单次完整重跑24项通过，没有导航重试或错误路由兜底。最终390报告在`wallet-390-verified/report.json`，320在`wallet-320/report.json`。这支持转场竞争的判断，不能证明已重现原始触摸根因。
- 成员押金缴纳入口在当前夹具中不可用，未制造资金来解锁；俱乐部负责人未验证手机号，取消验证后核对草稿及无付款单，最低额服务端拒绝另由真实PG集成覆盖。SDK不把这些未走通分支计为实际付款通过。
