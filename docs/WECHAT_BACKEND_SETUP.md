# 微信身份、手机号与支付管理配置

本文说明服务器如何启用本轮新增的正式微信能力，以及本地测试与正式环境的区别。秘密只写入服务器私密环境文件，不放进前端、Git、聊天或截图。

## 环境和首位管理员

正式服务使用 `APP_ENV=production`、`DEV_MODE=false`。启动时只建立游戏目录，不创建默认用户、默认管理员或可登录的演示账号。`/auth/dev` 和 `/me/phone/dev` 在正式环境返回 404。

`WECHAT_APP_ID` 与 `WECHAT_APP_SECRET` 必须对应当前小程序。微信官方身份先换取五分钟一次性票据；用户主动勾选当前两份协议后才能建立账号和会话。客户端传入任意 OpenID 无效。

首位管理员通过服务器私密变量 `BOOTSTRAP_ADMIN_OPENID` 指定。该值必须是运营者本人在当前 AppID 下的 OpenID，应由可信运维从私密 `identities` 记录核对获取，不能依据他人提交的字符串、昵称或客户端角色授予。用户先普通微信登录后也可以配置此变量并重新登录。

官方微信接口返回的 OpenID 与配置逐字精确匹配后，服务在同一个登录事务内授予管理员、写入审计和 `settings/bootstrap-admin` 一次性记录。完成后移除该环境变量并重启；已授予的权限保留。已有一次性记录时不会再次授予，即使该用户后来被降权。不要删除一次性记录来绕过权限管理。该过程不会在 API、日志或审计中公开 OpenID。

## 手机号

`/me/phone/wechat` 只接收 `wx.getPhoneNumber` 返回的 `code`。服务器使用微信 `stable_token` 和 `getuserphonenumber` 官方接口兑换，核对水印 AppID 和时间，再保存私密手机号。原文不出现在用户公开资料；本人只收到验证状态与脱敏号码。

小程序是否具有手机号权限取决于微信实际审核与开通状态。权限不足、用户拒绝、凭据过期或官方兑换失败时都会明确失败，不把客户端点击视为认证成功。真实环境下，开发绑定的手机号不能通过发布服务、发布需求或下单的服务器认证门槛。

## 支付管理

服务器设置 `CONFIG_ENCRYPTION_KEY`，值为独立随机 32 字节的 Base64 编码。私密环境文件权限应为 600，并应单独备份此密钥；丢失或更换它会导致已存商户配置无法解密。它不是微信 AppSecret，也不是商户 APIv3 密钥。

管理员在小程序内配置商户号、商户证书序列号、APIv3 密钥、商户 RSA 私钥、微信支付平台公钥及其 ID、支付和退款通知地址。通知地址必须使用 HTTPS。服务器将配置以 AES-GCM 全量加密保存到 PostgreSQL；界面只返回秘密是否已配置，秘密输入留空表示保留原值。可以分次保存草稿，所有必填配置完整且通过格式校验后才允许真实支付。配置完整不代表已完成真实商户联调，仍需官方权限和真实支付退款验收。

既有 `WECHAT_PAY_*` 环境配置继续兼容；一旦管理员保存支付资料，以管理配置为准。服务启动读取配置并发布内存快照，交易持锁期间不会再获取数据库连接。当前部署为单服务实例；若以后增加多个副本，保存后需同步重启其他副本以加载同一配置。

当前域名的通知路径可设为：

- `https://game.ai.58it.cn/api/payments/wechat/notify`
- `https://game.ai.58it.cn/api/payments/wechat/refund-notify`

## 演示数据

`demo_` 前缀的用户、俱乐部、服务和订单用于展示。任何关联演示资源的订单不能支付、接单、交付、退款、裁决或同步资金；微信支付/退款回调也不能修改演示订单。演示资料不能用于真实交易验收。

## 自动检查

身份协议和手机号通过本地真实 HTTP 微信替身、独立 PostgreSQL schema 与独立 Redis 前缀验证。支付协议测试使用一次性 RSA 测试密钥，覆盖请求/响应签名、回调验签、重放、退款补偿及配置秘密隔离。测试不会声称微信官方已授权或真实扣款已成功。
