# 公共信息、管理中心与交易页面开发计划

文件作用：记录本轮已经用户确认的范围、并行职责和验收顺序，防止功能扩张时遗漏权限、资金边界或先行设计要求。

## 已确认范围

1. 平台轮播与当前游戏轮播独立配置；全局一个游戏槽按当前位置展开多张游戏图。原服务素材池不变。原生swiper三秒切图，独立文字层延迟300毫秒，支持手动滑动、指示点和拖动排序。
2. 公共信息后台配置轮播、首页公告、四主页面顶部提示及服务／需求注意事项。目标只允许服务、需求、文章，ID或名称搜索后选择。公告可用原比例图片或多行文字，每次进入首页或按版本一次；登录按账号保存，访客在本机保存，真正展示后确认。
3. Markdown文章的管理员编辑、预览、发布和下架；访客可读的文章列表与详情，个人中心文章入口。安全解析，禁止原始HTML、危险链接和非托管图片。所有新图文字段复用AI／人工后置审核。
4. 微信更新下载完成后强制确认重启；资金操作期间延后，失败不阻塞业务。需要两版本真机验证，不能把本地mock当实际升级。
5. 个人中心统一菜单字号、头像昵称上移、可复制公开用户ID，手机号移至资料、协议合一；俱乐部中心进入发现页，创建旁放管理入口并支持多组织选择。钱包主金额和箭头移左，去卡片标题／说明，资金限制保留钱包详情及弹层。
6. 服务评价仅有完成验收订单的买家每单一次；服务详情3条和独立更多页。后端资格、唯一性、售后限制和后置审核继续保留。
7. 平台手机号搜索、安全用户列表和用户详情；基础资料编辑、状态、站内消息及钱包／订单／审核等相关分页记录。新增平台副管理员，后端禁止其授撤任何管理员或修改根管理员。
8. 俱乐部成员详情、相关订单、图文审核、仅本俱乐部收入与托管押金。负责人可授副管理员，副管理员不能继续授撤或变更负责人，成员离会撤权。副管理员可发起组织资金申请，实际收款人与微信确认始终为原负责人；记录真实操作者。
9. 订单详情重排层级，突出状态、金额和当前主操作；聊天室单独页面，订单底部固定入口，原聊天、图片、调价、退款与裁决证据及访问权限完整保留。
10. 排查配置与展示的多行文本，统一保留换行，不把标签、金额、搜索等单行字段误改为多行。

最新首页约束：只替换原顶部图片区域为轮播，已要求的提示控制在该区域内；保留原文字、按钮、目录、分类、搜索、卡片及价格布局。用户认可生成图的盾牌视觉，仅局部用于更小的黑金押金／真实认证角标，不引入“金牌打手”虚构认证。

## 实施职责与顺序

- 根任务：新分支、公共内容前端／运营后台／文章／轮播／公告、微信更新、评价展示与订单聊天室迁移、整体验收与提交。
- 公共内容后端：独立运营记录、文章及公告确认、目标搜索、托管上传、安全Markdown、多行注意事项与实际管理俱乐部筛选。
- 权限后端：根／副管理员、用户与成员详情、范围资金及所有后端越权测试；不直接修改余额。
- 管理前端：对应先行设计，个人中心、用户／成员详情、俱乐部入口和副管理员资金确认边界。

先准备`design/pages/`对应目录及同名前缀的390×844设计图／说明，再写页面；接口契约分别固定在`PUBLIC_CONTENT_API.md`及`ADMIN_CENTERS_API.md`。共享路由由根统一注册，后端共享文件按双方约定顺序接线。禁止把运营功能写进私人消息队列或复制第二套交易评价系统。

## 验收门禁

- 前端类型、44页及新增页规范、全量测试、H5和正式微信构建、七页分享钩子；开发包固定本地接口，正式包固定HTTPS域名。
- 后端真实本地PostgreSQL／Redis隔离集成、race与vet；角色伪造、跨成员／跨俱乐部、分页、角色撤销、收款绑定、原支付及审核竞争必须覆盖。
- 微信模拟器320／390检查轮播与独立文字、公告关闭、横向边界、换行、排序、跳转、访客列表和六种身份；原输入焦点、资金浮层、充值不可提现和切号隔离不退化。
- 实际微信更新、好友分享、手机号、订阅及支付到账分别记录验证边界。生产操作只用宝塔MCP，先备份再按已授权范围部署；任何资金与证据不能凭演示记录生成。
- 提交只含本轮代码、设计和脱敏验收；不含密钥、`.env`、会话、机器备份或私密运维资料。完成发送约定邮件并播放任务声音。
