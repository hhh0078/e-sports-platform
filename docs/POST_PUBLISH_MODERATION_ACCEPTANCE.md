# 后置图文审核与交互修复验收（2026-10-23）

文件作用：记录本轮已确认范围、实际检查结果、生产交付状态和用户测试步骤；区分自动化、微信模拟器、真实模型、真机与真实资金证据，不沿用旧包结果。

实施依据为[本轮确认计划](POST_PUBLISH_MODERATION_PLAN.md)，开发依据为[项目规范](../PROJECT_DEVELOPMENT.md)。本记录中的“通过”仅对应下述检查层级，不能理解为微信真人登录、真实 AI 审核或商户资金已经通过。

## 本轮行为

- 俱乐部创建与编辑显示字段限制和实时计数；前后端按去除首尾空白后的 Unicode 码点计数，避免中文、表情与后端长度判断不一致。名称为 2—30 字、介绍为 10—1000 字、考核最多 1000 字、加入备注最多 2000 字，成员申请及审核说明最多 500 字。
- 四个主视图保留原生滚动容器，取消滚动位置的循环回写；卡片共享视口信息并合并测量，隐藏视图停止测量，图片懒加载并提前保留布局空间。详细范围与性能复核方法见[滚动稳定性记录](SCROLL_PERFORMANCE_ACCEPTANCE.md)。
- 已有账号登录后直接回到目标页；只有首次注册显示可跳过的资料完善弹层。头像昵称保存不再因 AI 未配置而卡住。
- 合法格式和权限校验成功后正常保存，业务记录与字段级审核任务在同一事务提交；没有 AI 或 AI 故障时进入人工待审。自动审核提示“预计20秒左右”，人工待审不承诺20秒完成。
- 新增独立“平台管理 → 图文审核”页。管理员可按状态查看完整队列、读取原文与鉴权图片、人工通过或拒绝、请求 AI 重试。先行设计为[审核页设计图](../design/pages/manage/moderation.png)和[设计说明](../design/pages/manage/moderation.design.md)。
- 审核拒绝按字段类型处理公开内容，并发送包含原因和站内修改入口的消息；图片撤销覆盖同一图片的其他公开引用。交易聊天、交付、退款和调价原证据隔离保留，平台管理员依权限查证；普通展示只返回遮罩后的内容。

组织认证、手机号门槛、押金、资金金额和费率仍按原有独立规则执行。图文进入人工待审不等于俱乐部已获得组织认证，也不等于任何资金流程已经通过。

## 用户优先测试清单

先确认测试所用小程序包与后端属于同一版本。人工拒绝会修改公开展示并撤销图片，请使用专门的测试账号、测试图片和测试订单，避免对真实正常内容做试验。普通用户、打手、俱乐部负责人和平台管理员需分别检查权限。

### 1. 俱乐部长度提示

- [ ] 打手页进入俱乐部列表并打开“创建”，填写前应能看到名称和介绍限制，输入时计数更新。分别尝试名称 1／2／30／31 字，介绍 9／10／1000／1001 字；越界提示应指出具体字段，输入草稿不丢失。
- [ ] 使用中文和单个表情测试计数；前端允许的合法输入不应再被后端报成无说明的长度错误。含多个码点的组合表情按码点计数，不按视觉上的单个字形计数。
- [ ] 俱乐部装修分别检查考核、加入备注、图文段落；加入备注和段落换行应保留。申请加入和审核说明的超限错误同样应明确。

### 2. 已有用户登录和资料

- [ ] 用已有头像昵称的账号退出再登录，应直接回到原目标页，不反复弹“完善资料”。新注册账号仅首次显示弹层，可关闭继续使用。
- [ ] 在 AI 未配置时修改昵称、头像和简介；格式合法应保存成功并提示等待人工，不能因“AI未配置”卡在登录流程。手机号验证等交易门槛仍独立保留。

### 3. 无 AI 的人工审核

- [ ] 管理员保持 AI 关闭或未配置；普通用户发布/修改服务、需求、个人资料、俱乐部图文。保存应成功，页面提示“等待人工审核”，不要求等待模型返回。
- [ ] 管理员进入“平台管理 → 图文审核”，看到对应业务 ID、字段与内容。人工通过后状态更新；拒绝必须填写原因并二次确认。图片只能经管理员鉴权读取。
- [ ] 普通用户和俱乐部负责人打开审核页或请求审核原文，应被拒绝；不能因知道任务 ID 而读到他人原文。

### 4. 有 AI 的审核与故障回退

- [ ] 管理员配置自己的可用地址、模型和密钥后，提交合规文字与测试图片；应进入自动审核，状态以真实模型结果为准，预计20秒属于轻提示而非保证时间。
- [ ] 在独立测试配置中模拟超时、返回格式错误或不支持图像；保存仍应成功，任务转人工待审，管理员可继续通过/拒绝或请求重试。不能把故障显示为“审核通过”。
- [ ] 真实服务的图文识别能力、误判、漏判、耗时和费用需另做小样本检查；本轮自动化使用模拟模型，未证明上述能力。

### 5. 拒绝结果、消息与图片引用

- [ ] 拒绝测试昵称、服务标题或说明：公开页面应显示字段适配的审核失败提示；拒绝电话/微信号后应清空受限字段，不能把中文提示句当联系方式展示。
- [ ] 作者从消息中心打开拒绝消息，核对字段、原因和“修改个人资料／修改服务／修改俱乐部资料”等有效入口。读后本地仍保留全文，服务器仅删除本人已读副本；再次进入不应重复生成同一处罚消息。
- [ ] 先修改同一字段，再处理旧任务；旧任务不能覆盖新内容。连续改成 A→B→A 后，旧 A 的审核也不能覆盖最后一次 A。人工与 AI 同时处理时只允许一个有效结果生效。
- [ ] 同一测试图片被头像、封面、图文或其他公开位置引用后，拒绝源图片；相关公开位置都不应继续展示原图，旧媒体地址返回统一审核失败占位，原图片字节被撤销。
- [ ] 单独访问一个普通不存在的资源地址；应保持普通 404／缺失语义，不能误显示“该图审核失败”。替换或加载失败后原占位高度应稳定。
- [ ] 重新查看服务、需求、个人和俱乐部的公开分享落地及海报信息；被拒绝的公开字段不能通过分享接口再次露出。

### 6. 交易原证据和权限

- [ ] 测试订单发送文字与图片，提交交付/退款/调价理由后，由管理员拒绝其中测试内容。普通参与者的展示应被遮罩，订单金额、付款、费率及协商状态不因图文审核被更改。
- [ ] 平台管理员通过受权限保护的证据入口仍能查证原始内容；买家、打手、俱乐部负责人和无关用户不能读取这份隔离原证据。公开违规图片撤销不能导致原交易证据灭失。
- [ ] 四类身份跑一次下单、接单、聊天、退款/介入回归。涉及真实资金必须使用独立小额真实订单核对微信账单，不能使用演示或本地测试付款宣称到账。

### 7. 滚动和页面稳定性

- [ ] 在 320、390 宽和真实手机分别浏览长服务列表、俱乐部图文；加载图片前后不能明显推挤后续内容，隐藏标签页不应持续测量封面。
- [ ] 向下浏览到非零位置，切其他主标签后回来；位置和筛选应保留。打开服务详情后正常返回，不能主动跳回顶部或整页白屏重建。
- [ ] 分别测试冷图、缓存图、快速向下和向上滑动、惯性停止以及顶部/底部边界；记录设备、网络和短视频。微信的边界弹性与页面主动回写造成的跳动需分别判断。
- [ ] 打开审核详情、换账号、切页后回来；旧原文、原因和临时图片不应回填新账号，关闭浮层后不残留在普通页面。
