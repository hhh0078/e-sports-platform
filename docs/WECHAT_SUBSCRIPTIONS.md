# 微信订阅消息配置与测试

文件作用：说明2026-10-24最终六类微信提醒、真实模板配置、用户入口、发送日志和真人验收边界。

## 只发送六类重要提醒

| 场景 | 接收人 | 触发条件 | 点击后 |
| --- | --- | --- | --- |
| 服务新订单 | 服务打手 | 真实支付及托管核验成功，仍待接单 | 对应订单 |
| 退款申请 | 订单打手 | 买家提交退款申请，申请仍待处理 | 对应订单 |
| 打手接单 | 买家 | 打手接受订单 | 对应订单 |
| 入会申请 | 当前俱乐部负责人 | 玩家提交待审批的入会申请 | 俱乐部控制台 |
| 俱乐部订单争议 | 订单所属俱乐部当前负责人 | 挂靠订单申请平台介入，仍处于争议中 | 对应订单 |
| 俱乐部待认证 | 有效平台管理员 | 新俱乐部满足创建押金条件并进入审核 | 平台俱乐部管理 |

未付款订单、普通聊天、浏览、钱包、调价、审核和普通交付不新增微信提醒。演示订单不进入真实发送。新入会提醒按用户确认的“提交申请时”触发，不等到审批通过。

取消、退款撤回、已审批等失效待办不会继续发送或消耗授权。发送前同时复核当前负责人、用户角色、订单归属和当前小程序身份。

## 用户在哪里授权

- 打手发布服务成功后，轻提示中点击“接收新订单提醒”，可以稍后再说。
- 买家在服务详情、发布需求及本人订单中订阅接单结果。
- 打手在本人订单及消息中心设置中订阅退款申请。
- 俱乐部控制台订阅入会申请和订单争议。
- 平台控制台订阅俱乐部申请。
- “消息中心 → 微信提醒”统一管理本人的接收偏好；普通用户只能看到前三类，负责人增加两类俱乐部提醒，平台管理员增加平台申请提醒。

官方授权只在用户点击的同一调用栈内发起；保存后的异步回包只显示平台自己的提示层。拒绝、关闭或上报失败不影响发布、下单和已经成功的业务导航。每次最多申请三个不同模板；同一模板不能因为多个场景被虚增为多次机会。

一次性订阅不是永久授权。“总是保持以上选择”仅省去后续询问，不保证以后每个事件都能发送。接收开关是平台偏好，不是微信剩余权限保证。

## 管理员配置

进入“平台管理 → 微信订阅”，使用“模板配置”和“发送记录”两个页签。

1. 展开对应场景，点击“选择微信模板”。系统从当前AppID读取真实模板，仅显示用途匹配、type2且字段受支持的模板。
2. 按模板填写固定业务来源。选择模板只生成草稿，不自动启用；确认来源后再开启场景。
3. 开启总开关并保存。正式环境会重新核对模板属于当前AppID、标题用途正确、字段完整；保存失败应按提示修正。
4. 用户必须使用新版本小程序主动授权。配置完成不代表用户已经订阅，也不会回填历史订单。

当前真实模板采用以下映射；完整模板ID保存在服务器配置，不硬编码进源码：

| 场景 | 微信模板 | 字段 → 来源 |
| --- | --- | --- |
| 服务新订单 | 交易提醒 | 商品信息→服务名称；支付金额→事件金额；下单时间→真实下单时间 |
| 退款申请 | 退款申请通知 | 商品名称→服务名称；金额→事件金额；申请时间→事件时间；申请人→相关玩家昵称；原因→安全概要，原文在订单内查看 |
| 打手接单 | 接单成功提醒 | 服务名称→服务名称；订单编号→订单编号；接单时间→事件时间；接单人→相关玩家昵称 |
| 入会申请 | 新成员邀请通知（无电话版） | 所属团队→俱乐部名称；昵称→申请人昵称；时间→申请时间；备注→入会待审批概要 |
| 俱乐部争议 | 订单异常通知 | 订单名称→服务名称；备注→争议概要；通知时间→事件时间 |
| 俱乐部待认证 | 商家入驻申请通知 | 商家名称→俱乐部名称；申请人→负责人昵称；申请时间→事件时间；状态→待认证 |

用户原有四个微信模板保留。为使上述场景和必填字段匹配，本轮已在微信当前“休闲娱乐”类目添加接单成功、无电话版成员邀请、商家入驻申请三个一次性模板；没有发送测试消息。含联系电话的旧成员模板不用于本功能，不编造或泄露手机号。

## 发送状态与重试

站内消息与微信任务在原业务事务中保存，微信在事务提交后异步发送。消息已读删除不会使同一业务事件重新通知。

发送记录区分排队、发送中、微信已接受、模板未配置、用户关闭、缺少授权、身份不可用、已失效、明确失败和结果未知。界面中的“已发送”表示官方接口接受，不能证明用户手机弹出横幅或本人已阅读；手机通知、免打扰等仍由微信和用户控制。

只有明确尚未送出的任务支持安全重试。网络超时、发送中进程中断和不完整响应属于结果未知，不自动重发，也不提供盲目重试按钮。记录不回显OpenID、访问令牌或原始交易证据。

## 可选官方事件回调

模板发送复用现有`WECHAT_APP_ID`和服务端`WECHAT_APP_SECRET`，不新增前端密钥。

若需接收微信拒收、授权和发送结果事件，在微信后台“开发管理 → 开发设置 → 消息推送”配置：

- URL：`https://game.ai.58it.cn/api/wechat/messages`。
- 数据格式：XML。
- Token：与服务器私密环境`WECHAT_MESSAGE_TOKEN`一致；这是单独的回调校验值，不是AppSecret。
- 安全模式EncodingAESKey：与`WECHAT_MESSAGE_AES_KEY`一致。配置AES后服务端拒绝明文回调。

已有其它消息回调时应先确认统一转发，不能直接覆盖。服务端校验签名、时间、小程序身份和重复事件；官方接受事件不会在客户端记录之外再加一次候选。未配置回调时接口明确503，不伪装启用；显式客户端授权仍可按官方发送结果处理。未知发送不依据用户和模板猜测为已送达。

## 优先真人测试

- [ ] 用真实打手发布服务，点击提醒按钮，同意订阅；由另一真实买家支付非演示订单，核对微信服务通知及订单落地。
- [ ] 打手单独订阅退款申请；买家提交申请后，只有对应打手收到通知。撤回后才消费队列时不再提醒。
- [ ] 买家订阅接单结果，打手接受订单，核对买家收件和详情跳转。
- [ ] 负责人订阅入会申请，新用户提交申请，核对俱乐部名称、申请人及审批入口；无需传电话号码。
- [ ] 负责人订阅订单异常，由旗下真实订单发起争议；无关俱乐部不收到通知。
- [ ] 平台管理员订阅俱乐部申请，新俱乐部满足押金并提交认证后收到待审提醒；未缴足草稿不提醒。
- [ ] 拒绝授权、关闭平台偏好、取消提示、切后台再返回，业务都能继续；成功发布不能因订阅网络失败而重复提交。
- [ ] 同一真实订单重复回调只产生一条通知；同一人兼任多角色不能无理由重复接收。
- [ ] 检查后台发送记录。没有权限、失败和未知结果不显示为手机已收到，退款申请通知不声称退款到账。

自动化使用隔离PostgreSQL/Redis、受控微信HTTP及原生授权替身；模拟accept不是真人订阅，也不是微信收件证明。正式小程序需要上传新包后才能使用新增授权入口。
