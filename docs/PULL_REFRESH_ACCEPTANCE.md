# 下拉刷新与触底加载验收

文件作用：记录2026-10-24全站刷新分页改造、自动化与模拟器检查证据，区分代码验证和手机实际体验。

## 已实现

四个主导航内容支持官方下拉刷新，列表触底自动读下一页；24个可变二级页面启用原生下拉。普通刷新与加载更多按钮移除，错误态保留轻量重试，付款／退款／转账原单同步等业务操作保留。

沿用原`design/pages/`对应图片的布局，先补充29份页面交互设计说明。主四容器继续常驻，二级继续原生页面滚动，没有新增套叠纵向滚动层，也不循环写回`scroll-top`。

- 偏移按服务端原始条数推进，ID去重；第二页失败不丢前页、不跳页，重试沿用失败时的刷新／追加方向和查询快照。
- 未确认的搜索草稿不通过触底提交；筛选、身份或会话变化撤销旧交互锁，旧回包不能覆盖新列表或关闭新动画。
- 服务、玩家／俱乐部主页服务、评价、管理、账目和组织提现支持分页；服务评价与俱乐部提现可读取100条以后的历史。
- 资金历史按本人及组织用途先筛选再分页，不读取其他人的原单。触底不重复读余额结算、不触发付款同步POST。
- 钱包、管理配置、下单说明和聊天草稿保留；订单下拉也只读刷新调价记录，普通调价刷新按钮移除。
- 聊天从顶部加载较旧消息并保留阅读锚点；新消息轮询不抢走正在浏览历史的位置。
- 消息先完整同步并持久保存，再确认已读删除服务器副本；触底只分批展示本地历史。俱乐部成员已全量返回时采用本机分批渲染。
- 官方`uni-load-more`继续复用，针对其不被微信支持的图片标签选择器做精确构建兼容，不修改`node_modules`。

## 用户优先测试

1. 玩家首页停在顶部向下拉，刷新结束后游戏、类别和搜索条件保留；打手、订单、我的也分别试一次，访客空态应可刷新。
2. 管理员进入用户／服务管理，连续滑到最底，自动追加下一页且无重复；到底显示小字，不再有普通加载按钮。
3. 列表第二页加载时断网，已有卡片应保留。恢复网络点击错误重试，应接着原页；刷新失败重试不能误读下一页。
4. 搜索框只输入但不确认，触底不能自动切换新关键词。明确搜索后再分页，只能出现新筛选的数据。
5. 服务详情填写说明、钱包打开金额弹框、管理员编辑未保存配置，再尝试下拉；草稿和弹框应保留，不创建付款或重复提交。
6. 消息打开后本机仍有已读历史；上下滚动只展开更多本机记录，不会漏收服务器未读消息。
7. 长订单聊天上拉到顶部读旧消息，新消息到来时不应把阅读位置拉回底部。
8. 320／390两宽及实际手机检查：短列表、空态、返回和主导航切换均无白屏、横向溢出或刷新动画不结束。
