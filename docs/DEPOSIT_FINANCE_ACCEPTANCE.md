## 4. 押金与封面视觉矩阵

### 4.1 最终文字和角标规则

- 最新确认采用统一黑金盾牌角标，列表贴齐封面右上，短标仅左下圆角；不能随游戏主题变成醒目的彩色大按钮。
- 系统标题在上、分类/认证标签在下，都在图片底部悬浮；整体适当上移，缩短到图下价格区的空隙。渐变从顶部透明过渡到底部与卡片背景一致。这是当前最终顺序。
- 用户自定义文字仍是独立图层，存储文字、颜色、背景、位置和字号，不合成到图片；系统标题、标签及押金需要预留区域。
- 价格、单位、成交数与操作放图片下方正常文档流。不能隐藏文案、压成几像素字号、裁掉长标题来消除碰撞；密集详情可适度增高。
- 个人平台/成员俱乐部押金只用后端当前有效实缴，退款中金额退出保障标识；0元、未知金额、负数和非整数不能展示实缴证明。

### 4.2 执行矩阵

| 维度 | 必须覆盖 |
| --- | --- |
| 视口 | 微信实际320、390逻辑像素；保持字体与安全区可读 |
| 入口 | 首页精选卡片、打手我的服务、公开个人主页、编辑/发布预览、服务详情；订单引用卡片沿用共享规则 |
| 自定义文案 | 无文案、1条、6条长文案；英文长串、中文长串、emoji；不能静默隐藏条目 |
| 位置 | 左/中/右 × 上/中/下九种；六条同一位置也要依次排开 |
| 样式 | 小/大字号、浅/深文字、实色/透明背景、不同游戏背景 |
| 系统文字 | 短标题、长标题、分类/认证标签、长单位、较大价格 |

## 5. 三类押金、分账与来源审查操作验收

### 5.1 押金缴退

| 类型 | 缴纳入口 | 退款前提 | 必查失败/重试场景 |
| --- | --- | --- | --- |
| 个人平台押金 | 我的钱包 → 平台押金 → 自愿缴纳 | 双方均无待付款、履约或售后未决订单 | 自愿不阻断发布接单；重复点击、取消支付、部分退还、剩余不足1元仍可按实际分额退；未知结果查询原单 |
| 成员俱乐部押金 | 俱乐部主页 → 我的成员押金 → 缴纳加入押金 | 退出认证，关联履约及售后结束 | 不能借别的俱乐部押金通过认证；负责人不能提现/自行扣罚；按原支付单逐笔原路退 |
| 俱乐部平台押金 | 创建草稿 / 负责人控制台 → 俱乐部资金 | 所有认证成员为0，且该组织关联在途、售后订单均为0 | 只要有认证成员就拒绝；退还与新增认证/接单并发不能穿透；审核拒绝也有资金页退款入口 |

申请退款即将该金额移出有效保障；若微信退款结果未知，资金维持退款中并同步原单，不能用换新请求号“重试”导致重复退款。门槛修改、历史组织补缴和0元免缴的规则详见财务模型。

### 5.2 分账与钱包

1. 管理员 → 交易规则，分别设置自由打手、俱乐部挂靠平台费率；负责人 → 加入规则与装修，设置本组织抽成。
2. 用无挂靠服务、有效挂靠服务和公开需求分别下单，核对冻结的费率版本、组织归属、平台费、俱乐部费及打手净收入。
3. 示例10元实付、平台5%、俱乐部10%：平台0.50元、俱乐部1元、打手8.50元。该例不是系统默认费率；自由和挂靠两档平台费不能同时叠加。
4. 另用奇数分金额核对：两项费用分别以实付为基数向下取整，余数归打手，合计严格等于实付；比例合计不得超过100%。
5. 修改当前费率后，旧订单的比例和金额不变。公开需求创建时冻结平台两档，领取仅选已冻结平台档位并冻结当时俱乐部抽成，不能套用后来平台费率。
6. 已付款履约净收入进入“进行中”；验收后进入“结算中”；满7天且无争议才进入“可提现”。退款撤回原三方分配，组织佣金不进入负责人的个人钱包。
7. 充值只可消费，个人/成员/组织押金不能挪为消费或提现；“提现中”单独冻结。无完整来源的历史余额不凭订单状态补造可提现收入。

### 5.3 来源审查及管理员处理

1. 准备五笔各20元可分配净收入，提交100元提现；逐笔核对订单实付、抽成、支付凭证和可占用来源。不要直接改写钱包汇总余额制造收入。
2. 再覆盖充值余额消费、收入余额再次消费、混合余额付款、部分提现，沿每个上游批次追溯付款根。充值余额自身不能直接提现。
3. 平台管理 → 资金审核 → 原申请，查看“付款 → 订单 → 收入 → 本次提现”、来源编号、付款凭证、对应订单、本次分配和异常原因。
4. 来源之和须与申请金额相等，且付款、归属、商户/AppID、结算及售后、历史消费/退款、其他提现占用均匹配。缺失来源、重复占用、异常链、已退款来源与生产混入开发付款根必须拒绝。
5. 管理员“审核并发起转账”前须重新读取来源；后端执行时再次确定性核验。拒绝须保留理由并恢复未出网资金；已出网申请只同步原单，不能拒绝解冻或另建单出款。
6. 个人和俱乐部各自按上海自然日每天最多一笔有效申请；同一幂等号重放不加次数，处理中/成功占次数，最终失败/拒绝可重新申请。
7. 收款确认成功不等于到账；只以验签通知或原商户单查询的终态更新账本。未知结果继续冻结。组织佣金提现至当前负责人实名微信，保留申请人、收款人和来源快照。

后端 `financial_integration_test.go`、`financial_regression_test.go` 覆盖的具体场景须以实际测试输出确认；未开启PG/Redis集成测试时，不能把这些场景记为已验收。
