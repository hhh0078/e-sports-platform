## 本轮覆盖的关键行为

- 运营文案为独立纯文字，历史背景配置不再绘制；服务卡片文字的背景配置保持原能力。首页顶部删除固定品牌、分享按钮、发布需求、旧口号和游戏副文案，系统安全区与轮播指示点保留，下方游戏目录、分类、服务卡和价格不重排。
- 首屏等待当前游戏的服务端最终轮播数组，不先展示临时游戏封面。深链游戏先于首轮运营读取确定；公开读取不等待本人接口。同值刷新保留当前图，真实排序或审核投影变化仍更新，空数组不补造轮播，冷热失败分别处理。
- 顶部提示使用无底色的黄色文字与图标；公告关闭入口为弱边框圆形图标。原始图片、运营文字和服务文字仍是独立数据。
- 两篇正式默认文章、平台首图和透明新人公告使用稳定ID；新装只自动应用一次，已有站点显式应用且先备份，保留旧轮播，只补空白提示与须知。后续重启或重复执行不覆盖管理员修改。
- 服务新建／编辑和需求新建分别按账号、表单类型、编辑对象保存本机草稿。恢复需明确选择；失败保留、成功条件清理；游客独立，不自动迁入登录账号。资金、身份、押金和服务端附加属性不作为草稿保存。
- 服务页只保留一个原`ServiceCard`预览，位于全部用户字段之后、发布须知及提交之前；需求页不新增预览。
- 公共静态缓存TTL为86400秒，管理修改和审核后主动失效；同事务失效队列支持故障恢复，旧代际回填不能进入新缓存。鉴权、钱包、订单、聊天、私密关系、公告账号已读及交易资格保持实时读取。

先行设计和开发范围见`docs/DEVELOPMENT_PLAN_HOME_ONBOARDING.md`；缓存及默认内容部署规则见`docs/PUBLIC_CACHE.md`。

### 服务新建、服务编辑与需求草稿

以下三种入口分别完整执行一次：发布新服务、编辑自己的一条已有服务、发布新需求。

- [ ] 填写游戏、标题、说明、价格；服务再设置底图、文字颜色／背景／位置／字号、标签及有效挂靠。退出后重新进入，出现“发现未发布的草稿”，恢复内容与输入一致。
- [ ] 服务A与服务B分别编辑并退出；回到各自编辑页只询问自己的草稿。新建服务草稿与编辑草稿、服务草稿与需求草稿互不混用。
- [ ] 选择“不用并删除”后再次进入不再询问旧稿；关闭或点遮罩只关闭询问，退出再进入仍可选择恢复。
- [ ] 在同一页面前往钱包后返回、手机号授权取消后返回，输入保留且不反复弹恢复框。
- [ ] 模拟提交失败或手机号授权取消，当前输入和草稿保留；恢复网络后可以继续提交。
- [ ] 服务发布／编辑返回成功后草稿立即清理，随后隐藏、返回、退出不会重新保存成功稿；订阅提醒拒绝不影响成功结果。
- [ ] 需求成功创建待支付订单后草稿即清理，跳转到该订单。取消微信付款应从原订单继续，不从旧草稿重复创建需求单。
- [ ] A账号保存未提交草稿，切B账号不出现A的输入或恢复框；B保存后切回A仍可恢复A自己的草稿。A旧请求迟到不能清理B稿或替B导航。
- [ ] 游客填写后登录，游客稿不自动合并到账号；恢复／删除旧弹框的迟到点击不作用于新账号。
- [ ] 慢网首次进入时只显示准备状态；初始化失败显示重试，不出现可以提前输入后又被清空的表单。重试成功后原有效草稿仍可恢复。
- [ ] 过期登录状态下直接分享／深链进入发布页，原会话失效后能显示游客表单，不永久停在加载；仍需登录才可发布。同账号普通返回不重复询问恢复草稿。
- [ ] 新建和编辑页把某字段改掉后迅速恢复初始值，退出重进不恢复已撤回文字；多次快速输入只恢复最终输入。
- [ ] 本机存储满或草稿损坏时有可读提示；正常表单仍能使用，不删除其它账号或其它页面的新稿。此项在测试环境模拟，不清理真实用户设备数据。
