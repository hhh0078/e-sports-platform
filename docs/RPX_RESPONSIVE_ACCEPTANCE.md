# 全局 rpx 响应式改造验收

文件作用：记录全项目尺寸适配的实现范围、复测方法、实际证据和能力边界；不将构建或模拟器结果当成真机与真实资金验收。

## 设计与实现

沿用 `design/pages/` 已确认的390px页面设计，按 [响应式设计依据](../design/RESPONSIVE_LAYOUT.md) 映射750rpx。全部41个页面/视图、共享组件和全局样式统一处理间距、字号、圆角、图片、按钮与图标；不调整资金规则和接口。

- 共享 `design-units.ts` 统一设计尺寸换算。官方 uni-icons 字形与外框使用同一个rpx值，玩家图标遮罩跟随外框缩放。
- 服务卡片与详情按窗口宽度换算系统文案、押金与安全区的预留区域，再交给封面防重叠引擎；实测位置保持px，不进行二次缩放。窗口变化时重新测量，发布页原生滑块仍使用其接口要求的实际像素。
- 交易曲线先测量实际画布宽高再绘制。分享海报、好友图和朋友圈图保留真实位图尺寸。
- 保留1px细线、44px主要操作触控下限、微信原生状态栏/胶囊/安全区、真实视口断点与桌面内容上限。不能把这些数值机械替换成rpx。
- 个人中心沿用已修复的图片渐变、上移身份和紧凑订单区。充值余额与可提现收入保持分开记账，底行标明“充值余额（仅消费）”。

`check:standards` 通过现有PostCSS解析器检查CSS/样式块中的视觉固定px；动态内联样式由共享换算方法、相关执行测试及模拟器测量补充验证。未安装新依赖。

## 复测方式

连接现有微信开发者工具自动化端口后，使用官方SDK及CLI保存原始截图：

```bash
UI_TEST_PROJECT="$PWD/frontend/dist/dev/mp-weixin" \
UI_TEST_OUTPUT_ROOT=output/rpx-responsive \
UI_TEST_RESPONSIVE=1 \
UI_EXPECT_WIDTH=320 \
frontend/node_modules/.bin/tsx scripts/mini-background-smoke.ts
```

断开SDK后通过微信工具切换为390px设备，将 `UI_EXPECT_WIDTH` 改为390再执行。不要在SDK运行期间改代码、重新构建或切换设备。脚本只操作访客公开界面，不登录、不付款、不写后台或游戏偏好；使用官方原图，不重绘截图。
