# 订单协商调价与微信分享开发计划

文件作用：记录用户2026-10-23明确确认的业务规则、实现分工、接口及验收范围，作为本轮持续开发与交付依据。计划条目不代表已经验收通过。

## 已确认规则

- 打手提出加价，买家接受后支付独立补款，只有服务端核验成功才改变订单实付与分账。
- 买家或打手都可提出减价，提出方提交即表达本人同意，对方明确接受后按原支付凭证逐笔退差。
- 正常履约中允许协商加减价；已完成且资金尚未结算只允许减价；已结算、已退款或售后争议中的订单不自动调价。
- 微信付款差额按微信原路退款，银行卡付款不承诺退零钱；平台余额付款恢复原充值/收入分区，禁止把不可提现充值变成商家转账。
- 所有调整保留原因、发起人、双方确认及系统聊天证据。平台和俱乐部管理员可审阅，不替代双方同意。
- 首页、服务、需求、个人主页及俱乐部主页统一提供好友分享、朋友圈分享、实时海报。海报底部左侧为当前分享人头像昵称，右侧为真实小程序码；好友和朋友圈分别准备5:4和1:1图片。
- 提现沿用新版商家转账接口与小程序原生收款确认，复核获批场景、实名、回调与原单查询；配置仍仅管理员可见。

## 实施顺序和边界

1. 保留用户代码基线，新建 `codex/order-adjustment-sharing`；完整读取项目规范后先准备对应设计图、说明。
2. 订单后端增加独立调价、收款分笔、退款分笔；原支付根凭证不变，净金额与分账另行累计，沿用原订单费率。
3. 订单前端复用共享API工具、独立调价组件、明确确认及补款/退款进度，长原因可换行；旧订单和加载失败不猜金额。
4. 分享后端新增永久目标映射、匿名公开需求及小程序码接口；前端统一分享面板、Canvas海报、公共落地与单页模式。
5. 将补款和部分退款按实际成功时间纳入统计，钱包/押金退款/结算复核调价在途状态。
6. 完成静态检查、真实本机PG/Redis隔离集成与竞态测试、前端测试、H5与正式微信构建、320/390实际界面检查；提交推送并邮件通知。

不得向分享公开完整验收要求、订单聊天、支付凭据、手机号或管理页参数。二维码映射永久保存在PG；Redis仅缓存图像。不得把普通占位二维码冒充真实小程序码。生产、真实扣款及真实转账不作为本地模拟测试的一部分。

## 接口约定

### 订单调价

- `GET /orders/:id/adjustments`：返回当前订单的公开调价记录数组。
- `POST /orders/:id/adjustments`：`{kind:increase|decrease,amount_cents:正差额,reason,request_id}`。
- `POST /orders/:id/adjustments/:adjustment_id/respond`：`{action:accept|reject|withdraw}`。
- `POST /orders/:id/adjustments/:adjustment_id/pay`：`{channel:wechat|balance,request_id?}`，返回调价记录、订单、支付模式及必要的微信临时参数。
- `POST /orders/:id/adjustments/:adjustment_id/sync`：查询原补款/退款状态，不换单重发。
- 记录状态：`proposed/awaiting_payment/paying/refunding/completed/rejected/withdrawn/expired/refunded`；`refunded`表示迟到补款已原路退还。
- 无签名404及网络未知保持原资金冻结，通过原单同步恢复。确认未创建时，仅在创建租约结束、固定支付期限已过且官方查询/关闭双重可信不存在后受控结束；真正迟到实付隔离后原路退还，不阻塞新的正常协商。
- 订单展示原金额、累计实付、累计退差、当前净金额以及原比例下的净分账；不把私密商户、OpenID或交易号暴露给客户端。

### 分享

- `POST /shares`：登录分享人提交 `{kind:home|service|request|player|club,target_id,game_id?}`，身份只来自服务端会话。
- `GET /shares/:id`：匿名重新确认目标仍可公开并返回公开元数据。
- `GET /shares/:id/code`：返回官方真实小程序码图片；上游JSON错误、配置缺失或图片异常明确失败。
- `GET /jobs/:id`：匿名公开需求，只返回既有 `PublicJob` 脱敏字段，不能复用完整私密订单。
- 元数据 `path` 不带前导斜杠且不含查询，`query` 单独保存；原生好友回调由前端组成以 `/` 开头的完整路由。小程序码使用 `pages/shares/detail` 与永久32位分享ID。

## 必测矩阵

- 买家/打手/负责人/平台管理员/无关账号的读取、发起、同意和资金操作权限。
- 加价拒绝/撤回/过期、补款取消/重复通知/超时/迟到成功；减价双方确认、微信多笔部分退款、混合余额原分区恢复、后续全退。
- 并发提出、双击同意、支付与减价、调价与验收/结算/售后/退押金，不能重复扣款、退款、分账或产生无来源可提现款。
- 原冻结费率、1分钱舍入及多次调整累计守恒，个人与组织提现逐笔溯源，GMV和退款跨日事件不改写历史。
- 五类页面的好友/朋友圈/海报；访客、长名称、空头像、下架/取消/被领需求、二维码故障、图片下载失败、旧账号生成结果失效及320/390边界。
- 朋友圈单页场景1154无需登录、不能依赖私密接口；原生分享菜单及图片路径/比例/有效兜底。
- 新版商家转账确认、回调和查询以官方核验状态为准，不把HTTP200或本地确认当作到账。
