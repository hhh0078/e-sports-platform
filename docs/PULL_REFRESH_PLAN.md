# 全站下拉刷新与触底加载实施计划

文件作用：记录2026-10-24用户确认的改造范围、原生滚动设计、分页数据边界与验收要求。

## 已确认范围

四个主页面、可变列表和只读详情支持下拉刷新；具有下一页的数据触底追加。保留搜索、游戏、身份筛选、原有记录和滚动位置。删除普通刷新与加载更多按钮，错误态保留轻量重试，资金同步等业务操作保留。

## 设计与交互

- 沿用`design/pages/`同路径现有390宽设计图和已认可布局，先更新各页设计说明中的交互状态，不重新排列卡片。
- 主页面保留四个常驻官方`scroll-view`，仅可见容器开启官方下拉刷新和触底事件；不回写`scroll-top`。
- 二级页保留原生页面滚动，仅按名单开启`enablePullDownRefresh`，共享生命周期入口必须在成功、失败、受阻和隐藏时停止动画。
- 列表底部共用官方`uni-load-more`，显示“继续上拉加载／正在加载／已经到底了”；失败保留原记录并可重试。短列表、空列表也允许下拉。
- 表单、配置、登录、编辑与支付弹层不参与重置；草稿、金额、实名和聊天输入保持。管理配置与发送记录共页时，刷新只作用列表或独立只读状态。

## 分页与安全

- 原始返回条数决定偏移，按ID去重；刷新、换筛选、切号和隐藏使旧请求失效。连续触底只发一次，失败不推进分页。
- 玩家／俱乐部主页服务和服务评价接真实分页；俱乐部提现历史补权限保护的分页；成员已完整返回时只分批展示。
- 消息中心继续完整同步并可靠落盘，再确认已读删除服务器副本；触底只扩大本机渲染窗口。
- 订单聊天使用顶部加载旧消息，与底部新消息轮询分离，保留当前阅读锚点。
- 不修改资金计算、支付原单、退款幂等、审核规则及六类订阅范围。

## 验收

1. 执行真实业务函数测试，覆盖重复触底、刷新与追加竞争、失败重试、筛选切换和切号迟到回包。
2. 类型、规范、前端测试、Go定向及必要回归、H5与正式微信构建通过。
3. 微信开发者工具320／390两宽检查真实手势、空态、长列表、切页位置和弹层草稿。
4. 程序化生命周期、SDK滚动及真实手势分别记证据；不将模拟器结果等同手机性能、微信真实授权或真实资金验收。
