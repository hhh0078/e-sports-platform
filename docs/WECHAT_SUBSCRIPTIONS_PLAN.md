# 微信订阅消息开发计划

文件作用：记录2026-10-24用户最新收窄后的订阅消息范围、实现顺序和验收边界，作为本轮开发与交付的依据。

## 已确认范围

- 打手收到已核验实付的新订单：`provider_order`。
- 打手收到买家的退款申请：`provider_refund`。
- 玩家收到打手已接单的通知：`buyer_accepted`。
- 俱乐部负责人收到新成员通知：`club_member`。
- 俱乐部负责人收到旗下订单已申请平台介入的争议：`club_dispute`。
- 平台管理员收到满足创建条件、正式进入待认证的新俱乐部申请：`admin_club`。

只有上述六类新增业务提醒同步进入站内消息及微信队列；原有审核拒绝等站内消息保持原有流程，不额外新增资金、调价、普通交付或审核的微信通知。微信提醒受用户授权、偏好、有效模板及官方权限限制。普通聊天不逐条推送，普通公告不自动转成微信群发。

## 开发顺序

1. 核对业务状态及微信官方订阅规则，建立六个固定事件和接收人的明确映射，不提供任意扩大范围的开关。
2. 先完成用户提醒设置、管理员订阅配置及发送记录的390×844设计图和说明，再实现页面与共用提示组件。
3. 在业务事务内写入结构化通知与发送任务，提交后由后台发送；不解析聊天室文案，不在资金/订单锁内调用微信。
4. 建立持久幂等标记、有限重试、领取租约与日志。网络结果未知时保留未知状态，不盲目重发；站内已读删除不删除幂等事实。
5. 用户直接点击明确按钮后调用微信订阅接口。发布服务、买家下单和相关控制台提供对应入口，不因异步保存自动拉起官方授权。拒绝、模板缺失、微信开关关闭和H5均不阻断业务。钱包、调价和图文审核页不增加微信授权入口。
6. 管理员独立配置场景、模板与官方字段映射，发送记录不泄露OpenID、令牌或原审核证据。服务端复用已有微信身份及官方访问凭证。
7. 通过自动化、真实存储并发、H5/正式微信构建及320/390微信模拟器检查后，提交推送。服务器工作仅使用宝塔MCP，保留旧资金与业务数据。

## 配置和官方边界

模板必须来自当前小程序实际类目允许的模板库，不能仅凭拟定名称视为已配置。通过宝塔MCP已只读确认当前小程序类目为“休闲娱乐”，现有四个一次性模板为新成员邀请通知、订单异常通知、退款申请通知、交易提醒；其具体字段和用途必须逐项匹配。管理员可以直接读取官方已有模板和字段，不复制身份秘密到前端。

源码默认关闭微信发送，真实环境仅在匹配模板配置完成后按最新授权启用；站内业务通知继续正常工作。一次性同意不等于长期订阅，“总是保持以上选择”也不代表无限发送。客户端上报仅是候选授权报告，微信接口及签名事件为最终权限/结果依据。为补齐当前模板缺失而新增适用模板属于本轮用户明确授权；不得为凑字段泄露或编造联系电话。

官方当前允许一次请求最多五个模板，本产品每次只请求当前业务相关的最多三个、且标题不同的模板。新版服务动态卡片属于另一类按业态接入的能力，本轮使用弹窗订阅方式，不能混用模板及发送接口。

参考：[官方弹窗订阅指南](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message.html)、[授权接口](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/subscribe-message/wx.requestSubscribeMessage.html)、[发送接口](https://developers.weixin.qq.com/miniprogram/dev/server/API/mp-message-management/subscribe-message/api_sendmessage)。

## 必须验证

- 前端类型、规范、全量测试，H5及正式微信构建；正式包指向正式HTTPS域名。
- 四类身份的场景与配置权限、跨账号迟到响应、拒绝/关闭/取消授权、模板未配置。
- 事件与业务同事务提交/回滚、重复回调、重复上报、同人多身份、多个发送worker、租约与未知发送结果。
- 未付订单不提醒，退款提醒仅指申请而非到账，演示资金不触发真实通知；通知失败不更改业务状态或资金，不改变原结算调度。
- 320/390宽下真实浮层、设置表单、发送记录和跳转入口。
- 真实模板、真人微信授权与服务通知收件独立验收；模拟发送和构建不能替代真实收件。
