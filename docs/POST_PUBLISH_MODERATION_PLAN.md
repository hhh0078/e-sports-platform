# 后置图文审核与交互修复计划

文件作用：记录用户2026-10-23确认的实施范围、阶段顺序与验收要求；交易原证据隔离保留，审核不修改资金事实。

## 已确认范围

1. 俱乐部创建与编辑统一Unicode码点计数和限制：名称2—30、介绍10—1000、考核最多1000、加入备注最多2000；成员申请与审核说明最多500，字段错误明确指向输入框。
2. 去掉四主导航原生滚动位置的循环回写，保留常驻视图位置；共享视口读取、合并封面测量、隐藏视图停止测量、列表图懒加载并保持几何，俱乐部详情图按可信宽高占位。
3. 登录响应明确首次注册状态；老账号不反复提示完善资料，新用户可跳过，资料保存不依赖AI配置。
4. 新增后置人工/AI审核模块与管理页面，沿用统一视觉与rpx设计。发布、修改和图片上传先完成合法格式/权限校验，正常保存后由队列处理。

## 字段和数据边界

| 内容类型 | 审核对象 |
| --- | --- |
| 用户资料 | 昵称、简介、头像、主页封面 |
| 服务 | 标题、说明、单位、自定义标签及封面文案；游戏图库图片及服务引用 |
| 俱乐部 | 名称、介绍、考核、加入备注、封面、图文段落及图片、公开联系方式与二维码 |
| 成员关系 | 申请说明、成员审核说明 |
| 需求和交易 | 用户需求标题、验收需求、交付/售后说明、调价理由 |
| 沟通和评价 | 订单聊天文字、图片、评价 |
| 平台公开内容 | 公告、游戏文案与图片、客服公开信息、平台消息；保留管理员来源与审计 |

不把金额、费率、状态、OpenID、认证手机号、实名和商户/模型秘密交给AI。联系方式拒绝后清空对应受限字段；不能把中文失败句写成电话号码。俱乐部组织认证、创建押金、账号冻结、手机号门槛及资金规则保持独立。

## 审核流程

1. 业务保存和审核任务原子提交，按白名单业务类型/ID/字段登记，记录单调版本与内容摘要。
2. 持久队列领取任务并设置有效期租约，在数据库事务外调用AI。无配置、超时、格式或图像能力故障进入人工待审；进程恢复后可继续处理。
3. 管理员可查看字段原文、鉴权下载图片，明确通过/拒绝或重新交给AI。页面关闭、隐藏、换号后清原文和临时文件。
4. 生效前核对字段版本和当前任务，避免旧任务覆写新内容及人工/AI竞争；重复处置不重复发消息。
5. 公开内容拒绝后按字段规则替换、撤销公开违规图片并清除字节，旧媒体ID仍返回失败图。普通404使用原有资源缺失语义。
6. 订单聊天、交付/退款/调价说明及截图不物理覆写原件，普通响应使用审核投影遮罩，平台争议审核依权限读取隔离证据。
7. 用户成功保存后轻提示自动审核预计20秒左右；无AI时提示等待人工。最终拒绝通过消息中心告知完整原因和修改入口。

## 验收顺序

1. 前端严格类型、规范、单元测试、H5及正式微信构建；核验正式域名与分享运行钩子。
2. 隔离PostgreSQL/Redis真实事务与并发测试：无AI可保存、人工通过/拒绝、AI允许/拒绝/故障、任务重启、旧版本、人工/AI竞争、图片字节撤销、消息幂等、证据保留与原资金幂等。
3. 微信模拟器320/390检查新审核后台、俱乐部错误与长内容、旧用户登录回跳、卡片与图片稳定布局；快速滑动单独记录，scrollTo几何通过不能冒充手势帧率。
4. 中文提交并推送，按已有上线授权通过宝塔MCP部署后端并验证正式环境健康和新接口。部署不等于微信包已上传审核，真实AI效果、手机手势与真实资金仍单独记录。

最终结果另记验收文档，不把本计划当作已完成证明。
