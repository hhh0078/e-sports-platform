# 首页运营与发布草稿、公共缓存开发计划

文件作用：记录2026-10-26两次已确认的本轮范围、先行设计、实施分工、默认内容和验收边界；本轮分支为`codex/home-onboarding-polish`。

## 已确认范围

1. 运营轮播文案为纯文字，保留字号、文字色、九宫格位置，忽略历史底色；编辑预览与展示一致。服务卡片文字的背景能力保留。
2. 删除首页图片区固定品牌、分享、发布需求、旧口号及游戏副文案，保留系统安全区和指示点；下方游戏目录、分类、搜索、服务卡片与价格不重排。
3. 后端保持统一排序和游戏槽原位展开；首屏等待当前游戏权威结果，不先展示临时游戏图。公共读取不依赖个人资料成功；深链优先、弱网换游戏、热返回与同值刷新不串图或无条件归零。
4. 顶部提示为鲜黄色文字和图标，取消底色、圆角和上方空隙，保留多行与可选文章跳转。公告关闭为弱边框圆形图标，保留足够点击区域、版本已读及防连点。
5. 原创平台轮播与透明异形新手公告，两篇正式文章。平台轮播首插而保留旧项；备份后替换单公告为仅一次；只有真正空白的提示和须知填默认。稳定ID、幂等操作、正常审核和审计，不随启动覆盖管理员修改。
6. 服务发布/编辑、需求发布按账号、类型、编辑对象保存草稿；进入询问恢复或不用并删除。失败保留、成功清理，切号隔离、游客独立且不自动合并，不能把服务端金额/身份/押金缓存为草稿。
7. 服务预览移至全部字段之后、提交提示之前，以分隔和标题与提示区区分；不新增需求预览，不修改共享服务卡。
8. 适合的公共静态数据使用Redis24小时缓存、修改主动失效；鉴权、钱包、订单、聊天、交易资格及私密关系实时。缓存命中不重复读取完整业务数据，旧回填、提交失败、审核撤图、Redis故障与进程恢复均覆盖。

## 执行与验收

先在`design/pages/`和`design/components/`准备同名前缀图片及说明，再分别实施首页、发布草稿和后端缓存。每个角色的私有数据与公共缓存严格区分，JSON不可整包缓存服务/俱乐部/个人主页动态资金。

必须通过前端类型、规范、单测、H5和正式微信构建；后端真实PG/Redis race及vet。微信官方SDK在320/390分别验收冷启动首图、热返回、长文案、透明公告、圆形关闭、草稿恢复/删除/成功清理/切号和预览顺序；失败与未覆盖均按实际记录。

完成后中文提交推送、经宝塔MCP备份/部署/默认内容初始化/只读验收；不使用浏览器或SSH，不造生产订单、付款或订阅。真实微信收付、订阅收件和真机升级继续单列边界。
