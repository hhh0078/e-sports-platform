## 资金与历史数据覆盖

测试在随机独立 PostgreSQL schema 和独立 Redis 键前缀运行，由测试清理逻辑回收；未修改线上或生产环境，未重启现有 API。

本轮全量测试实际包含：

- 平台自由打手、平台俱乐部挂靠两档费率，以及独立俱乐部抽成、整数分守恒、净收入和旧订单快照。
- 服务换挂靠并发窗口的锁序回归；公开需求领取选择原两档平台费率，合法零费率与旧版本快照不套用新价。
- 五笔订单来源审核、充值余额消费、收入余额再次消费、混合余额退款、递归追溯、跨商户拒绝、来源不可变及重复占用保护。
- 个人平台押金、成员俱乐部托管押金、俱乐部平台押金隔离；创建草稿幂等、实缴认证门槛、认证成员存在时拒绝俱乐部退款、退会后成员押金原路退还。
- 历史无来源收入不能提现；旧微信实付托管仅在官方原单成功退款已核验后反冲待结算并记录待核账，不补造来源。
- 旧混合余额退款核对原不可变付款分录，恢复原充值/收入分区且只入账一次；恢复的历史收入仍因缺少来源而不能提现。
- 新版托管来源全部缺失、部分缺失、缺版本但仍有新版分配凭证时均拒绝降级兼容，避免借历史退款跳过资金校验。
- 本人及俱乐部独立提现、每日并发次数、审核拒绝/失败恢复、签名/商户/金额/收款人校验，以及上游超时维持冻结并按原单查询。

## 客服权限与格式复核

平台客服保存必须为平台管理员；俱乐部资料保存复核组织负责人或平台管理员权限。平台二维码必须为当前管理员本人上传的对应用途图片；俱乐部二维码限制为编辑本人上传、对应组织或本人未绑定草稿。电话、微信号与二维码字节均进入内容审核，独立配置页按显式字段合并，bootstrap 仅返回公开白名单，不返回支付或 AI 密钥。

发现并修复了电话格式前后端不一致：后端原来只限制字符集，可能保存 `++`、`()`、1至2位数字或超过20位数字；客户端会拒绝拨号。修复后非空号码去除空格、括号和横线，必须为可选前导 `+` 与3至20位数字，格式化原文最多32字符。空值可清除配置，正常手机号、400号码、`+86` 带空格/括号格式保留。补充纯格式边界及平台/俱乐部 API 拒绝用例，修复后已通过定向竞态测试。

二维码白底合成只作用于透明的 `support_qr`、`club_contact_qr` 图片，普通头像透明度保留；规范化后的同一份字节用于模型审核、摘要、存储与公开预览。对应逐像素与数据库/HTTP字节一致性用例已包含在本轮全量测试。
