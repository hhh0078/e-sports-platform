# 输入控件聚焦稳定性

文件作用：记录2026-10-26输入框聚焦修复的共用交互依据；沿用`design/pages/`原有设计图，不改变页面布局、色彩或业务字段。

## 设计边界

- 以已有390宽设计图为基线，单行控件沿用`--control-height`及44px实际触控下限；320／390宽度分别验收。
- 未聚焦、聚焦、输入和失焦四种状态保持同一外框高度、字段间距及文字对齐。不得以焦点态的字体、padding或transform变化模拟修复。
- 原生单行`input.input`及H5外层`uni-input.input`移除上下padding，文字行高交给单行编辑器；水平内边距、底线和圆角沿用原设计。
- 开放式表单的`.form-section`显式保留上述单行规则，避免通用表单padding重新覆盖。
- 多行`textarea.input`保留现有内容padding、行高及独立高度；带图标或选择器的`view.input`保留Flex居中和原内边距，不套用单行编辑器规则。
- 搜索、金额、聊天、昵称与颜色等专用类仍须检查其局部声明；共享修复不使用`!important`压过业务样式。

## 键盘与数据

- 保留微信正常的键盘避让能力，不全局设置`adjust-position=false`。
- 聚焦上半屏控件不得无故改变整页滚动位置或背景布局；底部控件允许为避免键盘遮挡而进行必要移动。
- 不清空草稿，不主动保存支付资料，不调整权限、金额、请求或消息处理逻辑。

## 验收锚点

1. 平台配置支付页：商户号、证书序列号、公钥ID、长回调URL及密码框连续聚焦／失焦，其他字段外框和文本位置不跳。
2. 原生共享单行控件上下padding为0，行高为normal；H5外层控件保持等价规则。
3. 协议／简介等多行输入仍有原内边距并可正常换行；Picker与图标输入外壳仍Flex居中。
4. 用焦点前后的真实节点矩形、页面滚动值和截图区分文字基线变化与系统必要的键盘避让，不能只凭构建成功判定修复。
