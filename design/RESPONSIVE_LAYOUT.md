# 全局 rpx 适配依据

文件作用：本轮前端全部页面及共享组件的尺寸改造依据；沿用 `design/pages/` 现有390px设计图，不改变既有配色、内容层级及业务流程。

## 尺寸规则

- 现有390px设计图映射750rpx，视觉尺寸乘以750／390，390px宽时保持原设计大小。间距、字号、圆角、图片、按钮和图标统一使用rpx；页面宽度优先100%、弹性布局和受控换行。
- 主按钮保持44px实际触控下限；视觉高度可用rpx。1px细线、真实视口媒体断点、桌面内容最大宽度、原生状态栏／胶囊／安全区及实测布局坐标保留实际像素。这些是设备或布局边界，不随设计单位重复缩放。
- Canvas／海报实际位图和绘制坐标保持真实像素。可见图表外框按rpx适配，绘制必须采用实际测得的宽高，不能仍按旧固定像素高度绘制。
- 封面文字防重叠引擎已经根据实际容器计算位置和大小，输出的测量坐标继续用px；不得将同一坐标再当作rpx二次缩放。静态外观尺寸仍改为rpx。
- 图标尺寸由共享转换工具统一处理，不能只缩外框却保留图形原px字号。固定绘图、原生组件的专用尺寸按该组件接口单位处理。
- 钱包、退款、押金、提现、登录与权限逻辑不变；本轮不能通过隐藏文案、删除资金分区或缩成极小字号解决拥挤。

## 实施与验收

修改前读取对应 `design/pages/` 说明。此次为原设计的响应式落地，默认390图仍是设计基线；320/390实际截图放在output，不冒充先行设计图。

按共享组件、主导航／服务／社区页面、账户／订单／管理页面分区处理。检查动态内联样式和uni-icons，禁止仅对CSS字符串做无差别替换。既有本地修改保留。

完成后检查类型、规范、前端测试、H5／微信构建及实际微信模拟器。两种宽度分别核对四主导航、长文案、图片渐变、服务卡片、弹层和二级页；复查独立游戏主题、滚动和横向溢出。真实设备及真实资金能力另行验收。
