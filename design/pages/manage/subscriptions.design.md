# 微信订阅管理设计说明

文件作用：为独立管理员模板配置、发送记录与安全重试提供先行设计依据。

- 原生 ImageGen 先行设计 `subscriptions.png`，390×844；2026-10-24 制作。提示词：黑绿紧凑管理页、模板／记录双页签、场景折叠、模板ID和字段映射、单一保存按钮，无巨幅插画和蓝紫渐变。
- 使用 AppShell 统一返回。页签“模板配置 / 发送记录”，主开关、六类场景折叠。关闭场景仍可保存草稿；开启必须有模板ID和1—10个固定来源映射；关闭场景可保留完整配置或完全空配置，不可提交半配字段。
- 字段名由平台模板实际字段填写；来源只能选择服务端允许的标题、状态、金额、时间、订单号、对象名称、数量、摘要，不能配置任意URL／用户原文／登录或支付秘密。
- 发送记录显示标题、场景、状态、次数和脱敏原因，不显示 OpenID、令牌或订阅原文。仅服务端 can_retry 为真才展示“重试”，不确定结果不能盲目重发。
- 配置不是微信模板创建器；管理员需从微信公众平台选择当前类目可用的模板，填写准确字段。缺失配置时明确不可发送，不展示假成功。
- 加载错误始终可见、可重试。未登录、玩家、俱乐部负责人不能读取配置和记录；切换账号或隐藏页面清除草稿／记录，旧请求不能恢复。
- 320/390宽检查：输入框 block 100%、字段映射窄屏仍三列可用，长模板ID不撑宽，状态换行，保存按钮44px触控。

2026-10-24范围收窄：先重新生成六卡设计图，再修改页面。六项是打手新订单、打手退款申请、买家接单结果、俱乐部成员申请、俱乐部争议协助、平台俱乐部申请。每项业务事件由服务端硬编码，不提供复杂事件勾选；官方模板选择读取当前小程序真实已添加模板，只生成待确认映射，不默认启用。

本轮只提供type2一次性微信模板，type3长期和type4新版不列入选择；一次原生申请不能混用模板类型。正式启用仍由后端验证ID、类型与字段和当前小程序一致。发送记录error_code为官方数字结果码。

官方模板选择按当前六类场景固定标题白名单过滤，避免将退款申请模板选给接单结果；最终微信模板ID/类型/字段仍由服务端核验。

模板列表进一步排除空字段和不支持字段：仅thing／phrase／character_string／amount／number／time／date加正整数编号可选；同标题的新成员模板只列无电话版，不扩展phone_number类型。列表说明明确“仅显示本功能支持的模板字段”。
