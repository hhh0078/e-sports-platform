# 钱包管理

文件作用：本轮开发前的390×844确定性布局设计，沿用批准的深色游戏主题。

原有总览/曲线或商家转账配置保留；新增独立资金审核和交易规则入口，不将来源明细、密钥和业务表单堆回总览。

2026-10-23新版商家转账复核：保持原布局，仅将场景编号输入上限对齐官方36字符，报备字段名1—15字、内容1—32字，避免保存后到真实转账才因格式被拒绝。字段说明使用现有次要文本样式，不新增卡片。

设计数字只用于布局，不作为运行时数据；页面必须请求服务端真实金额。访客显示零或登录提示，加载显示占位，失败保留旧数据并提供重试。44px主操作、16px边距、14px次要文字；页面无主底栏，顶部统一返回。

## 合并后的管理员、资金与品牌边界（2026-10-23）

公共品牌统一为开机电竞。统一二级返回、无主底栏，开放分节和细分隔。默认待审核列表，真实状态筛选仅pending_review / processing / wait_user_confirm / success / failed / rejected或all，不向接口传虚构terminal筛选；空列表不制造用户或提现记录。

只有pending_review允许审核拒绝或审核后发起转账；处理中只能同步原单，发起前展示真实用户和金额摘要。开发模拟结果只在开发模式出现，生产不发送dev_outcome、不由客户端解冻未知资金。独立资金审核核对逐笔来源，不能凭订单状态造可提现收入。

公开转账配置为withdrawal_enabled、transfer_scene_id、transfer_scene_report_infos、transfer_notify_url、transfer_remark、user_recv_perception；最多10条报备，场景编号最多36字符，字段名1～15字、内容1～32字，说明32字、收款感知10字，通知地址为无查询参数HTTPS。旧版32字符场景编号和32字字段名上限已作废。

GET/PATCH返回settings、transfer_ready、configuration_notice；保存配置不等于商户场景获批。密钥、证书沿用独立支付配置，页面不读取或缓存秘密、OpenID、实名密文和收款package。隐藏、切号及筛选变化使旧响应失效；失败保留可修复草稿。冷启动错误显示在权限判断分支外，提供从init重新加载的入口。


## 2026-10-24 下拉刷新与连续加载

沿用本页同名前缀390×844设计图，不调整已确认的资金、导航或聊天布局。原生页面顶部下拉显示微信官方刷新反馈，完成、失败或被资金操作阻挡后均及时停止；失败保留已有数据和输入。所有刷新仅调用现有GET读取，不自动同步资金原单、不提交任何金额或配置。
下拉只刷新当前状态提现列表及通道状态，已编辑的公开转账草稿不得被覆盖；保存或读取配置时阻挡刷新。触底追加当前状态列表，页尾使用统一加载/无更多/重试状态。

错误重试必须记录原失败动作：下拉失败重读第一页，触底失败重试原始offset；不得根据旧hasMore决定。账号、会话和当前组织/服务端筛选变化作废共享手势锁，金额、实名和文字草稿不参与刷新上下文键。
