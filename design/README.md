# 集结页面设计目录

文件作用：列明本次先设计后实现的手机首屏目标，以及设计图与前端页面的对应规则。

本目录 `pages/` 与 `frontend/src/pages/` 镜像。每个页面/主视图包含同名前缀的 PNG 与 `.design.md`；图均由内置 ImageGen 独立生成后用系统图片工具等比例缩放，默认390×844。主容器 `main/index.png` 复用玩家设计表达共同框架，四个内容视图各自有独立设计。

## 制作顺序

1. 先生成并保存主页面玩家、打手、订单、我的四张图，通知主页面实现者读取后开始视觉改造。
2. 生成登录、资料、协议、服务详情、服务发布、需求发布六张图，保存后通知二级页面实现者。
3. 生成订单详情、俱乐部目录/主页/装修、玩家主页、后台目录/配置七张图，再通知实现者。
4. 对应页面先读取图和说明再实现；实际截图与差异验收保存在仓库 `output/`，不能替换先行设计图。

原始生成指令、对应文件和生成方式见 [prompts.json](prompts.json)。各页图是可读的首屏目标，不是要把整张图作为小程序背景；所有按钮、输入、标签、图片和文字都需用真实可交互组件实现。图中的游戏画面只示意构图，实际页面保持已核验的官方游戏素材。

## 页面覆盖

| 页面目录 | 独立设计 |
| --- | --- |
| `main/player`、`main/worker`、`main/orders`、`main/me` | 四个常驻主视图 |
| `account` | 登录、个人资料、协议、我的钱包、消息列表与详情 |
| `services` | 服务详情、服务发布/编辑 |
| `requests` | 需求发布 |
| `orders` | 订单履约、聊天、退款与介入 |
| `community/clubs` | 俱乐部目录、主页、装修 |
| `community/players` | 玩家主页 |
| `manage` | 管理控制台、用户、服务审核、俱乐部、订单售后、游戏、钱包审核、平台设置、协议与支付、操作审计、AI设置、平台消息发送 |

统一约定：黑绿自然主题、16px水平边距、8/12/16/24px间距、44px主按钮、36px次按钮和统一官方图标。四主视图没有应用顶栏，只预留系统状态栏/胶囊安全空间；图片开头的展示型二级页使用图上圆形返回，表单/配置和无封面玩家主页继续普通统一顶栏。二级页面均无主底栏。服务卡标签在上、标题在下，作为独立元素位于图底渐变内，价格和成交在图下正常流。源游戏图16:9，服务卡显示区按新版约4:3裁切。生成图示例数据不覆盖真实业务。

运行 `npm --prefix frontend run check:standards` 可检查 TypeScript、具名业务 API、唯一底栏以及设计图路径/尺寸覆盖。

## 2026-10-22游戏细化、钱包与独立管理模块

登录继续使用三角洲、王者荣耀、和平精英的官方素材组合，不恢复用户已删除的品牌和“先逛逛”。接单身份默认为开启且不可关闭，打手页状态与资料/个人中心说明均为静态呈现。个人中心保持当前选中游戏的动态封面、中性灰黑蒙版、独立头像与正常流统计，增加“我的钱包”轻入口。

钱包按真实账本区分充值、可提现收入、待结算、冻结和平台押金，不将充值作为可提现收入。订单付款选择微信或余额，使用实际可用金额判断。押金完全自愿，服务卡仅在实际有效金额大于零时于图下展示轻量标识；详情与发布预览沿用真实金额及非赔付说明。钱包和订单付款图中的金额为版式示例，运行数据以服务端为准。

后台先生成新的管理控制台图，核心指标、待办和真实交易曲线下方保留独立模块入口，最新增加AI设置与平台消息后共十二项；原页签和整段业务列表迁出。用户、服务、俱乐部、订单、游戏、审计与平台设置各有同名独立图和说明；钱包审核、协议/微信支付保留各自独立页面设计。名称/公告编辑仍在平台设置中，不因拆页丢失。图中的示例日期和混合状态行不能作为运行数据或覆盖真实筛选。

本轮旧图按变更点存入 `history/20261022-before-game-refinements/`、`history/20261022-before-deposit-badge/` 和 `history/20261022-before-admin-console/`。当前图、完整提示词和对应关系集中在 `pages/` 与 `prompts.json`，验收截图继续单独放 `output/`。

## 2026-10-22AI兼容接口与消息中心

先生成AI设置、管理发送消息、用户消息列表和详情四张独立图，再实现对应页面。AI默认模型严格为 `qwen3.8-flash`，兼容地址、提示词及密钥状态可配置；配置完整、本地模拟、真实连接是不同状态，页面只呈现后端实际结果，密钥不回显、不缓存、离页清除。图中计数已按实际后端提示词12000字、消息标题60字/正文5000字更新。

个人中心只追加同规格“消息中心”轻入口；管理控制台追加AI与发送消息两个独立入口，其他布局不重做，新增行自然滚动。消息列表仅标题和未读点，详情为完整纯文本。按账号保存本机全文；未读绝不删远端，点击详情并将已读状态落盘成功后才确认删除远端副本。用户图中的消息、时间、身份和审核结论都只用于排版，不能填充成运行数据。

## 2026-10-22统一游戏选择弹层

共享 `GameSelector` 沿用已批准首页的底部圆角弹层、搜索和三列游戏图标，不建立新风格。首页/打手横排与“全部”保留，服务/需求单选、多选俱乐部覆盖游戏全部调用同一组件，选择行为通过受控值交还父页面；业务表单不能改写首页偏好。

打开状态变体仍镜像页面目录并保留同名前缀：`main/player/player-game-picker.*`、`services/publish-game-picker.*`、`requests/publish-game-picker.*`、`community/clubs/edit-game-picker.*`、`community/clubs/index-game-picker.*`。五张图均为390×844，正常态PNG继续保留；worker只复用同一弹层并补说明。单选即选即回，多选先临时勾选、确认回填，取消不丢父草稿。俱乐部创建的游戏弹层必须位于原创建modal上方，关闭后返回该modal，不新增创建路由。

13个及未来配置游戏在限定高度内纵向滚动，320px仍保持三列，不挤窄相邻图标。蒙层使用rgba，游戏图片继续取正式素材；排序、服务分类、单位、挂靠、日期等其他原生picker不属此次迁移。
